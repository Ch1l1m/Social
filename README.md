# SocialNetwork.WebApi

Backend MVP для мини-социальной сети, построенный по принципам чистой архитектуры. Проект демонстрирует навыки проектирования реляционных баз данных, построения REST API, реализации асинхронных операций и автоматического юнит-тестирования.

## 🚀 Технологический стек

* **Платформа:** .NET 9.0 / C# 13
* **Веб-фреймворк:** ASP.NET Core Web API
* **ORM:** Entity Framework Core (Code-First)
* **База данных:** PostgreSQL
* **Документация API:** OpenAPI / Scalar API Reference (вместо устаревшего Swashbuckle)
* **Тестирование:** xUnit, EF Core InMemory Database

---

## 🛠 Архитектурные особенности и паттерны

1. **Code-First Миграции:** Вся структура базы данных спроектирована на уровне C#-классов и находится под строгим контролем версий. Обновления СУБД происходят хронологически цепочками миграций (`migrations add` / `database update`). Отказ от `EnsureCreated()` в пользу масштабируемости.
2. **Асинхронность (TPL):** Все операции ввода-вывода (I/O Bound) к PostgreSQL спроектированы асинхронно (`async/await`, `SaveChangesAsync`, `ToListAsync`), что освобождает потоки сервера (Thread Pool) и гарантирует высокую масштабируемость системы под нагрузкой.
3. **Паттерн DTO (Data Transfer Object):** Защита эндпоинтов от оверпостинга (Over-Posting Protection). Входные параметры контроллеров изолированы от живых моделей базы данных (`CreateUserDto`, `CreatePostDto`).
4. **Оптимизация LINQ-запросов:** Использование `.AsNoTracking()` для высокоскоростного чтения без затрат на отслеживание изменений (Change Tracker) и жадная загрузка связанных сущностей через `.Include()`.
5. **Изолированное Юнит-тестирование:** Тестирование бизнес-логики без загрязнения реальной базы данных с помощью виртуального провайдера `UseInMemoryDatabase` в оперативной памяти.

---

## 💾 Структура базы данных

Реализована реляционная связь **«Один ко многим» (One-to-Many)** между пользователями и публикациями:
* Один **User** может владеть коллекцией `List<Post>`.
* Каждый **Post** имеет строго одного автора и ссылается на него через внешний ключ (`UserId`) и навигационное свойство.

---

## 📡 Эндпоинты API (REST)

### Пользователи (`UsersController`)
* `GET /api/users` — Получить список всех пользователей (`AsNoTracking`, JSON).
* `GET /api/users/{id}` — Получить профиль конкретного пользователя по ID. Возвращает `404 Not Found`, если объект отсутствует.
* `POST /api/users` — Регистрация нового пользователя на основе `CreateUserDto`. Возвращает HTTP-статус `201 Created`.

### Посты / Лента (`PostsController`)
* `GET /api/posts` — Получить общую ленту новостей. Выполняется SQL `JOIN` через метод `.Include(p => p.User)` для мгновенной склейки постов с именами их авторов.
* `POST /api/posts` — Публикация нового поста от имени пользователя с предварительной проверкой существования автора (`AnyAsync`).

## 🧪 Покрытие тестами (xUnit)

Бизнес-логика покрыта автоматическими тестами. Тесты независимы от окружения:
* `AddUser_Should_Save_User_To_InMemory_Database` — Тестирует метод добавления пользователя по паттерну **AAA (Arrange, Act, Assert)** в изолированном контексте `InMemoryDatabase`.

## ⚡ Инструкция по локальному запуску

1. **Клонируйте репозиторий:**
   ```shell
   git clone https://github.com/ВАШ_ЛОГИН/SocialNetwork.WebApi.git
   ```
2. **Настройте PostgreSQL:** Убедитесь, что строка подключения в `ApplicationContext.cs` содержит ваш актуальный пароль от СУБД.
3. **Накатите миграции:** Откройте командную строку в папке веб-проекта и примените чертежи к базе данных:
   ```shell
   dotnet tool run dotnet-ef database update
   ```
4. **Запустите проект:** Запустите решение через Visual Studio или выполните команду `dotnet run`.
5. **Откройте интерактивную документацию Scalar:** Перейдите в браузере по адресу `https://localhost:7186/scalar/v1` для тестирования запросов.
